## Findings — Bugs et gaps identifiés

### Critique

| # | Sévérité | Zone | Description |
|---|----------|------|-------------|
| 1 | **CRITIQUE** | Formulaire contact | `src/app/api/contact/route.ts:30` contient un `TODO` — la route retourne `success:true` mais **n'envoie aucun email**. Tout visiteur qui utilise le formulaire contact reçoit un faux accusé de réception. |

### Important

| # | Sévérité | Zone | Description |
|---|----------|------|-------------|
| 2 | Important | Schéma DB | `ActivityLog.userId` est `String` (NOT NULL) avec `onDelete: SetNull` — impossibilité de supprimer un utilisateur qui a généré des logs d'activité. Fix : passer à `String?` + migration. Contourné dans le seed (cleanup manuel des logs avant delete). |
| 3 | Important | Events API | `GET /api/admin/events` exige COMMITTEE (`requireCommittee`) alors que `POST` accepte COACH (`TRAINING_ROLES`). Un coach peut créer un entraînement mais ne peut pas lister ses créations. Fix : aligner le `GET` sur `TRAINING_ROLES`. |
| 4 | Important | Proxy / pages admin | `src/proxy.ts` vérifie uniquement la présence d'un cookie de session, pas le rôle. Un MEMBER authentifié accède aux HTML des pages `/admin/*` (données vides car APIs répondent 403 → pas de fuite, mais UX dégradée : pages qui semblent cassées plutôt que page d'accès refusé). |

### Mineur

| # | Sévérité | Zone | Description |
|---|----------|------|-------------|
| 5 | Mineur | Profile PATCH | `PATCH /api/members/me` accepte `emergencyPhone` dans le payload mais la colonne DB est `emergencyContactPhone`. Payload silencieusement ignoré sur ce champ. Fix : aligner le nom dans le schéma Zod. |
| 6 | Mineur | API events | Pas d'endpoint `GET /api/events/my-registrations` — un membre ne peut pas lister ses inscriptions sans requêter tous les événements et filtrer côté client. Ajouter une route dédiée. |
| 7 | Mineur | ENV local | `STRIPE_SECRET_KEY` et `RESEND_API_KEY` vides dans `.env.local` → 500 sur `/api/stripe/membership`. Emails en fallback `console.log`. Comportement attendu en dev, mais à documenter. |
| 8 | Mineur | Blog create | `POST /api/admin/blog/posts` reçoit `status:"PUBLISHED"` mais le modèle utilise `published:boolean`. Le post est créé en brouillon, il faut un `PATCH` séparé pour publier. Schéma Zod à homogénéiser. |
| 9 | Mineur | Nav routes | `/admin` (racine) retourne 404 — pas de page index. Entrée par `/admin/dashboard`. Les membres sont à `/members` (pas `/admin/members`). Vérifier tous les liens internes. |

## Commande seed test consolidée

Ajout du script `pnpm seed:test` dans `package.json` :

```json
"seed:test": "tsx --env-file-if-exists=.env.local --env-file-if-exists=.env scripts/seed-test-accounts.ts"
```

Le script est idempotent : nettoie les `ActivityLog` des comptes test avant de supprimer les users (contournement du bug #2), puis recrée les 4 comptes avec mots de passe hashés BetterAuth directement via Prisma (évite `MISSING_OR_NULL_ORIGIN` du signup HTTP).

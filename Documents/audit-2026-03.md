# Audit Complet — Projet LADTC

**Date** : 2026-03-04
**Projet** : LADTC — site web du club
**Stack** : Next.js 16 / React 19 / TypeScript / Prisma / PostgreSQL / BetterAuth / Stripe
**Déploiement** : Vercel (CDG1 Paris) + Docker

---

## Résumé exécutif

Le projet LADTC est un site associatif complet avec gestion de membres, e-commerce (équipement), blog/événements, et dashboard admin. Le code est globalement **bien structuré**, avec un bon usage de TypeScript strict, Zod pour la validation, et une séparation des responsabilités claire. Les points d'amélioration principaux concernent la **sécurité** (XSS, en-têtes CSP), la **couverture de tests** (très faible), et quelques optimisations React.

| Dimension | Score | Détail |
|-----------|-------|--------|
| Architecture | ✅ Bon | App Router bien structuré, séparation claire |
| TypeScript | ✅ Excellent | Strict mode, pas de `any`, Zod partout |
| Sécurité | ⚠️ À améliorer | XSS, CSP manquant, dépendances vulnérables |

## 1. Architecture

### Points forts
- **App Router Next.js** bien organisé avec route groups : `(auth)`, `(public)`, `(member)`, `(admin)`
- **API RESTful** avec ~40 routes structurées par domaine
- **Hooks custom** (13 fichiers) encapsulent la logique data-fetching avec TanStack Query
- **Lib/** sépare la logique métier (auth, email, schemas, cart, stripe, csv)
- **Prisma** avec 14 modèles bien normalisés, indexes pertinents
- **CI/CD** GitHub Actions (lint → type-check → build → test → docker)

### Points d'amélioration
- `src/components/admin/` contient 18 fichiers à plat → organiser en sous-dossiers par feature (members/, products/, events/)
- `src/components/forms/` a 9 formulaires de complexité variable → grouper par domaine (auth/, profile/, admin/)
- Pas de middleware centralisé pour l'autorisation → chaque route API refait le pattern de vérification de rôle

### Recommandation
Créer un utilitaire d'autorisation centralisé :
```typescript
// src/lib/auth-guard.ts
export async function requireRole(allowedRoles: UserRole[]): Promise<Session> {
  const session = await auth.api.getSession(/* ... */);
  if (!session || !allowedRoles.includes(session.user.role)) {
    throw new AuthError("Unauthorized");
  }
  return session;
}
```

## 2. Sécurité

### 🔴 Critiques

#### XSS via `dangerouslySetInnerHTML`
**Fichier** : `src/app/(public)/blog/[slug]/page.tsx:123`
```tsx
const htmlContent = post?.content ? marked.parse(post.content) : "";
<div dangerouslySetInnerHTML={{ __html: htmlContent }} />
```
Le contenu Markdown est rendu sans sanitisation. Un admin malveillant pourrait injecter du JavaScript.

**Fix** : Installer `dompurify` et sanitiser avant rendu :
```tsx
import DOMPurify from "dompurify";
const htmlContent = DOMPurify.sanitize(marked.parse(post.content));
```

#### Credentials hardcodées dans docker-compose.yml
```yaml
POSTGRES_PASSWORD: ladtc
BETTER_AUTH_SECRET: dev-secret-change-in-production
```
Le fichier est commité dans git. Utiliser `.env.local` (déjà dans .gitignore) et un `docker-compose.override.yml`.

#### Headers CSP absents
Aucun Content-Security-Policy configuré dans `next.config.ts`. Noté comme TODO dans le roadmap du projet mais non implémenté.

**Fix** : Ajouter dans `next.config.ts` :
```typescript
headers: async () => [{
  source: "/(.*)",
  headers: [
    { key: "Content-Security-Policy", value: "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'" },
    { key: "X-Frame-Options", value: "DENY" },
    { key: "X-Content-Type-Options", value: "nosniff" },
  ]
}]
```

### ⚠️ Modérées

| Problème | Fichier | Détail |
|----------|---------|--------|
| Dépendances vulnérables | package.json | 6 HIGH, 7 MODERATE (minimatch ReDoS, serialize-javascript RCE, Hono auth bypass) |
| Logging de données sensibles | `api/contact/route.ts:31` | Email + message utilisateur loggés en console |
| HTTP fallback | `lib/auth-client.ts:7` | Fallback `http://localhost:3000` si env var absente |
| Port PostgreSQL exposé | `docker-compose.yml` | Port 5433 accessible localement |
| Pas de rate limiting | API routes | Aucun endpoint n'est protégé contre les abus |
| Webhook Stripe sans rate limit | `api/stripe/webhook/route.ts` | Pas de protection anti-replay |

### ✅ Bonnes pratiques respectées
- Prisma ORM → pas d'injection SQL
- Validation Zod sur tous les inputs
- BetterAuth pour l'auth (bcrypt, sessions DB)
- Vérification de signature Stripe webhook
- Docker avec user non-root (`nextjs`)
- `.gitignore` correct (pas de .env commité)
- Upload de fichiers avec validation type/taille

## 3. Qualité du code

### TypeScript
- **Excellent** : strict mode activé, aucun `any` détecté, types Zod inférés
- **À corriger** : castings `as` non sûrs pour les rôles utilisateur dans les API routes :
  ```typescript
  // ❌ Actuel
  (session.user as { role?: string }).role
  // ✅ Mieux : typer la session correctement
  ```

### Duplication
- **Minimale** : schemas centralisés, templates email consolidés, utilitaires extraits
- Pattern de vérification d'auth répété dans chaque route API → extraire en middleware

### Composants
- 7 formulaires > 150 lignes (BlogPostForm: 278, EventForm: 219, ProductForm: 192)
- `GalleryUploadForm` : 9 `useState` séparés → utiliser `useReducer`
- `MemberTable` : rendu conditionnel imbriqué sur >15 niveaux

### Naming
- **Excellent** : PascalCase composants, camelCase utils, UPPER_SNAKE constants
- Conventions cohérentes dans tout le projet

### Console.logs
- 3 `console.error` côté client (ProfileForm, MemberForm, EventForm) → utiliser Sentry
- 1 `console.log` de données sensibles (contact form) → supprimer

## 5. Performance

### Points d'attention
- **React.memo manquant** sur les composants de carte (ProductCard, BlogCard) rendus en liste
- **useCallback manquant** sur les handlers dans ProductForm (`toggleSize`), GalleryUploadForm
- **Pas d'optimistic updates** dans les mutations TanStack Query
- **Pas de timeout** sur les appels `fetch` → risque de requêtes suspendues
- **Images** : Next.js Image optimization configurée ✅

### Quick wins
```typescript
// Ajouter timeout aux fetch
const controller = new AbortController();
const timeout = setTimeout(() => controller.abort(), 5000);
const res = await fetch(url, { signal: controller.signal });
clearTimeout(timeout);
```
